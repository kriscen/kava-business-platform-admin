# 功能规范：后台管理前端项目基础架构

**功能分支**：`001-admin-frontend-scaffold`
**创建日期**：2026-03-13
**状态**：草稿
**用户描述**：从零开始搭建后台管理前端项目基础架构，先集成基础能力和基本功能，不涉及业务，只做最基础的项目搭建

## 用户场景与测试 *(必填)*

### 用户故事 1 - 项目初始化与开发环境 (优先级: P1)

作为开发者，我需要一个完整配置好的 React 项目脚手架，以便我可以立即开始业务开发，而不需要花费时间配置构建工具、代码规范和开发环境。

**为什么这个优先级**：项目初始化是所有后续工作的基础，没有它无法进行任何开发。

**独立测试**：可以通过运行 `npm run dev` 启动开发服务器，访问页面看到空白内容区，且 ESLint/Prettier 正常工作。

**验收场景**：

1. **假设** 开发者克隆项目后，**当** 执行 `npm install && npm run dev`，**则** 开发服务器成功启动，浏览器显示页面
2. **假设** 开发者编写代码后，**当** 保存文件，**则** ESLint 自动检查并提示错误，Prettier 自动格式化
3. **假设** 开发者执行 `npm run build`，**则** 项目成功构建，无报错

---

### 用户故事 2 - 布局系统 (优先级: P2)

作为开发者，我需要一个经典的后台管理布局组件（侧边栏+顶栏+内容区），以便我可以专注于业务页面的开发，而不需要重复构建页面框架。

**为什么这个优先级**：布局是所有页面的容器，在页面开发之前必须就绪。

**独立测试**：可以通过渲染布局组件，验证侧边栏可折叠、顶栏显示、内容区正常展示。

**验收场景**：

1. **假设** 布局组件已渲染，**当** 页面加载完成，**则** 显示侧边栏（左侧）、顶栏（顶部）、内容区（主体）
2. **假设** 用户点击折叠按钮，**当** 触发折叠操作，**则** 侧边栏收缩为图标模式，内容区自动调整宽度
3. **假设** 浏览器窗口宽度小于 768px，**当** 页面渲染，**则** 布局响应式适配移动端

---

### 用户故事 3 - HTTP 请求封装 (优先级: P2)

作为开发者，我需要一个统一封装的 HTTP 请求模块，以便我可以便捷地调用后端 API，且所有请求都自动包含统一的错误处理、请求拦截和响应拦截。

**为什么这个优先级**：前后端交互是后台管理系统的核心能力，需要尽早完成。

**独立测试**：可以通过发送测试请求，验证请求拦截、响应拦截、错误处理正常工作。

**验收场景**：

1. **假设** 开发者调用 `request.get('/api/test')`，**当** 请求发送，**则** 自动添加基础 URL 和请求头
2. **假设** 后端返回 401 错误，**当** 响应被拦截，**则** 自动跳转登录页或提示错误（预留钩子）
3. **假设** 后端返回业务错误码，**当** 响应被处理，**则** 统一提示错误信息
4. **假设** 网络请求超时，**当** 超过配置的超时时间，**则** 自动取消请求并提示超时

---

### 用户故事 4 - 状态管理 (优先级: P3)

作为开发者，我需要一个全局状态管理方案，以便我可以在不同组件间共享状态（如用户信息、应用配置），且状态变更可追踪、可调试。

**为什么这个优先级**：状态管理为跨组件数据共享提供基础设施，可在布局和请求模块完成后集成。

**独立测试**：可以在组件中读取和更新全局状态，验证状态持久化和调试工具正常。

**验收场景**：

1. **假设** 开发者在组件 A 中更新全局状态，**当** 状态变更，**则** 组件 B 中能获取到最新值
2. **假设** 开发者打开 Redux DevTools，**当** 状态变更，**则** 可以追踪状态变化历史
3. **假设** 页面刷新，**当** 状态配置了持久化，**则** 状态从 localStorage 恢复

---

### 用户故事 5 - 国际化基础设施 (优先级: P3)

作为开发者，我需要一个国际化框架，以便项目可以支持多语言，当前先支持中文，但架构预留扩展能力。

**为什么这个优先级**：国际化属于增强功能，不影响核心开发流程，可稍后集成。

**独立测试**：可以在组件中使用国际化函数获取文案，验证切换语言（预留接口）正常。

**验收场景**：

1. **假设** 开发者在组件中使用 `t('common.confirm')`，**当** 渲染组件，**则** 显示对应的中文文案"确认"
2. **假设** 项目需要支持英文，**当** 添加英文语言包并切换语言，**则** 显示英文文案（架构支持）
3. **假设** 缺少某个翻译 key，**当** 渲染组件，**则** 显示 key 本身作为降级处理

---

### 用户故事 6 - 错误监控与日志 (优先级: P3)

作为开发者，我需要全局错误捕获机制，以便可以及时发现和处理前端错误，当前阶段在控制台输出，为后续接入监控服务预留扩展。

**为什么这个优先级**：错误监控提升系统稳定性，但可在核心功能完成后添加。

**独立测试**：可以主动触发错误，验证错误被捕获并在控制台输出完整信息。

**验收场景**：

1. **假设** 页面发生 JavaScript 运行时错误，**当** 错误抛出，**则** 全局捕获并输出错误堆栈到控制台
2. **假设** Promise 发生未捕获的 rejection，**当** Promise reject，**则** 全局捕获并输出错误信息
3. **假设** 组件渲染发生错误，**当** 错误边界捕获，**则** 显示降级 UI 并记录错误

---

### 用户故事 7 - Mock 数据支持 (优先级: P3)

作为开发者，我需要 Mock 数据方案，以便在后端接口未就绪时可以独立开发调试前端功能。

**为什么这个优先级**：Mock 提升前端开发效率，但可在实际接口对接前准备。

**独立测试**：可以配置 Mock 接口，验证请求返回 Mock 数据。

**验收场景**：

1. **假设** 开发者配置了 `/api/user` 的 Mock 数据，**当** 发起请求，**则** 返回 Mock 数据而非真实请求
2. **假设** 后端接口已就绪，**当** 关闭 Mock 功能，**则** 请求发送到真实后端
3. **假设** Mock 数据需要模拟延迟，**当** 配置延迟时间，**则** 响应在指定延迟后返回

---

### 边界情况

- 当侧边栏菜单项过多时，如何处理？（假设：支持滚动，或分组折叠）
- 当 HTTP 请求失败且无网络连接时，如何提示用户？（假设：显示网络错误提示）
- 当状态管理存储大量数据时，是否影响性能？（假设：Zustand 本身轻量，需开发者合理设计状态结构）
- 当 i18n 语言包加载失败时，如何处理？（假设：使用默认语言，显示 key 作为降级）
- 当页面路由不存在时，如何处理？（假设：显示 404 页面）

## 需求 *(必填)*

### 功能需求

**项目初始化**

- **FR-001**：系统必须使用 Vite 作为构建工具，支持快速冷启动和热更新
- **FR-002**：系统必须配置 ESLint 和 Prettier，支持代码规范检查和自动格式化
- **FR-003**：系统必须使用 TypeScript，提供类型安全
- **FR-004**：系统必须配置路径别名（如 `@/` 指向 `src/`）

**布局系统**

- **FR-005**：系统必须提供经典后台布局组件，包含侧边栏、顶栏、内容区三个区域
- **FR-006**：侧边栏必须支持折叠/展开切换，折叠时仅显示图标
- **FR-007**：布局必须支持响应式设计，适配桌面端和移动端
- **FR-008**：布局组件必须支持自定义 logo、标题、菜单项

**HTTP 请求**

- **FR-009**：系统必须封装 Axios，提供统一的请求实例
- **FR-010**：请求必须支持自动添加基础 URL、超时配置、请求头
- **FR-011**：系统必须提供请求拦截器，支持请求前处理（如添加 Token 预留钩子）
- **FR-012**：系统必须提供响应拦截器，统一处理响应数据和错误
- **FR-013**：系统必须提供错误分类处理：网络错误、业务错误、权限错误

**状态管理**

- **FR-014**：系统必须集成 Zustand 作为全局状态管理方案
- **FR-015**：系统必须提供状态持久化配置选项（支持 localStorage）
- **FR-016**：系统必须支持 Redux DevTools 调试

**国际化**

- **FR-017**：系统必须集成 i18n 框架（react-i18next），支持多语言切换
- **FR-018**：系统必须提供中文语言包作为默认语言
- **FR-019**：i18n 必须支持动态加载语言包

**错误监控**

- **FR-020**：系统必须全局捕获 JavaScript 运行时错误，输出到控制台
- **FR-021**：系统必须全局捕获未处理的 Promise rejection，输出到控制台
- **FR-022**：系统必须提供 React Error Boundary 组件，捕获组件渲染错误

**Mock 数据**

- **FR-023**：系统必须集成 Mock.js，支持拦截 XHR 请求
- **FR-024**：系统必须支持按环境开启/关闭 Mock（开发环境开启，生产环境关闭）
- **FR-025**：系统必须提供 Mock 数据配置示例

### 关键实体

- **请求配置 (RequestConfig)**：包含基础 URL、超时时间、请求头、拦截器配置
- **布局配置 (LayoutConfig)**：包含侧边栏宽度、折叠状态、菜单项配置
- **应用状态 (AppState)**：全局共享的应用级状态，如侧边栏折叠状态、语言设置
- **错误信息 (ErrorInfo)**：包含错误类型、错误消息、堆栈信息
