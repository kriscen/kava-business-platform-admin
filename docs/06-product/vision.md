# Kava 产品愿景

## 产品定位

Kava 是一个以家庭为单位的多租户平台，为个人提供技术架构验证环境，同时作为未来应用生态的后端基础设施。

Kava Admin 是平台的管理控制平面，服务两类管理员：**平台管理员**（Kava 层面）和**家庭管理员**（租户层面）。

```
┌─────────────────────────────────────────────────────────┐
│                       Kava 平台                         │
│                                                         │
│    ┌───────────┐    ┌───────────┐    ┌───────────┐      │
│    │  家庭 A   │    │  家庭 B   │    │  家庭 N   │      │
│    │ ┌───────┐ │    │ ┌───────┐ │    │           │      │
│    │ │ App 1 │ │    │ │ App 1 │ │    │           │      │
│    │ ├───────┤ │    │ ├───────┤ │    │           │      │
│    │ │ App 2 │ │    │ │ App 2 │ │    │           │      │
│    │ ├───────┤ │    │ └───────┘ │    │           │      │
│    │ │ App N │ │    │           │    │           │      │
│    │ └───────┘ │    │           │    │           │      │
│    │ Members   │    │ Members   │    │ Members   │      │
│    └───────────┘    └───────────┘    └───────────┘      │
│                                                         │
│    Kava Admin ─── 管理控制平面（本项目）                  │
│    Kava 后端  ─── 基础服务 + 垂直业务（多租户隔离）       │
└─────────────────────────────────────────────────────────┘
```

## 用户与角色

| 用户类型  | 对应系统   | 身份       | 管理范围                      |
| --------- | ---------- | ---------- | ----------------------------- |
| UPMS User | Kava 后端  | 平台管理员 | 全局：租户、服务、平台设置    |
| UPMS User | Kava 后端  | 家庭管理员 | 本租户：App、Member、业务配置 |
| Member    | 各家庭 App | C 端用户   | 所属 App 内数据               |

- **平台管理员**：创建/管理租户，设置租户基本规则和资源限制，管理全局服务能力和平台设置。
- **家庭管理员**：入驻后管理本租户，注册家庭 App 接入 Kava 后端，管理 C 端用户和业务模块配置。

## 核心概念

### 租户（家庭）

平台的基本隔离单元。每个家庭是一个独立租户，拥有：

- 独立的数据空间（租户间数据隔离）
- 独立的角色和权限体系
- 可自主注册和管理的 App 集合
- 平台分配的资源配额

### App 接入

家庭开发的应用，通过 OAuth2 协议接入 Kava 后端：

```
家庭开发 App → 向 Kava 注册（clientId/clientSecret）
                → 配置权限 Scope
                → App 通过 OAuth2 认证 Member
                → App 调用 Kava 后端 API（租户隔离）
```

App 类型不受限制 — 可以是各种 ToC 垂直领域应用。

### 服务能力

Kava 后端提供双层服务：

- **基础服务层**：所有租户共享，包括认证（Auth）、用户权限（UPMS）、文件存储、消息通知、国际化等。
- **垂直业务层**：按租户按需启用的业务模块，如记账、家务管理等。平台管理员控制各租户可用的业务模块。

### 权限模型

```
平台管理员
  └── 配置租户可用业务模块（功能开关）
  └── 设置租户配额和规则

家庭管理员
  └── 管理本租户角色和菜单
  └── 管理 App 权限 Scope
  └── 管理业务模块内部权限

C 端用户（Member）
  └── App 内的权限，由 App 自行定义
```

## 功能模块

### 平台级（平台管理员视角）

| 模块         | 功能                                     |
| ------------ | ---------------------------------------- |
| Dashboard    | 平台概览、资源统计、告警                 |
| 租户管理     | 租户列表、创建/编辑/启停、配额设置       |
| 服务管理     | 基础服务状态、垂直业务模块注册、能力配置 |
| 全局用户     | 管理员列表、角色模板                     |
| OAuth 客户端 | 客户端列表、权限 Scope 管理              |
| 系统设置     | 公共参数、日志审计、国际化               |

### 租户级（家庭管理员视角）

| 模块      | 功能                         |
| --------- | ---------------------------- |
| Dashboard | 租户概览、用量统计           |
| 应用管理  | App 注册、配置、权限分配     |
| 成员管理  | Member 列表、分组、标签      |
| 业务模块  | 已启用的垂直业务列表和配置   |
| 租户设置  | 基本信息、角色权限、菜单配置 |

## 设计原则

1. **多租户隔离**：租户间数据严格隔离，App 只能访问所属租户数据。
2. **按需启用**：基础服务全局可用，垂直业务模块由平台管理员按租户配置。
3. **渐进式验证**：先完善基础管理面，再逐步接入业务应用，跑通全链路。
4. **个人技术验证优先**：作为架构能力验证项目，优先保证架构清晰和技术方案的合理性。

## 平台角色与 Admin 视角映射

```
登录用户角色判断
       │
       ▼
┌──────────────┐     ┌──────────────┐
│  平台管理员？  │──否─▶│  租户管理员   │
│              │     │              │
│  看到：       │     │  看到：       │
│  · 全局菜单   │     │  · 租户菜单   │
│  · 所有租户   │     │  · 本租户数据  │
│  · 平台设置   │     │  · 租户设置   │
└──────────────┘     └──────────────┘
```

Admin 根据登录用户的角色动态渲染菜单和页面，两种角色看到的模块和操作范围完全不同。
