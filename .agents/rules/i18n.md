## i18n 开发规则

所有用户可见的字符串（按钮文字、标签、提示、错误消息、表头等）必须通过 i18n `t()` 函数引用翻译 key，不得直接硬编码在组件 JSX 或逻辑代码中。

### 翻译文件结构

- 翻译文件按功能模块拆分，放在 `src/i18n/locales/<locale>/` 目录下
- 当前仅维护 `zh-CN` locale
- 通用字符串放在 `common.json`，布局相关放在 `layout.json`，各业务模块独立文件（如 `user.json`、`role.json`）
- `src/i18n/index.ts` 会自动加载 `locales/zh-CN/` 下所有 JSON 文件

### key 命名规范

- 格式：`<模块>.<含义>`，使用 camelCase
- 通用 key：`common.confirm`、`common.cancel`、`common.save` 等
- 模块 key：`user.username`、`user.email`、`role.roleName` 等
- 引用时使用 `t('common.confirm')` 格式

### 验证

新增或修改翻译 key 后，运行 `pnpm dev` 确认页面正常显示，控制台无翻译 key 缺失警告。

### Why

硬编码字符串无法支持多语言扩展，集中管理翻译 key 提高可维护性。

### How to apply

在编写新组件或修改现有组件时，检查所有用户可见字符串是否已通过 `t()` 引用。如果新增翻译 key，同步更新对应的翻译文件。
